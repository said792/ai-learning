## 🐳 النشر على VPS (Docker)

```bash
# ضع مفاتيحك في .env.local ثم:
docker compose up -d --build
```

الصورة تشمل كل حاجة جاهزة: **ffmpeg** (الفيديو) و**LibreOffice** (الصيغ القديمة) والخطوط العربية.

### بدون Docker (VPS مباشر)

```bash
# متطلبات النظام
sudo apt-get install -y ffmpeg libreoffice fonts-noto-core

npm install
npm run build
npm start   # يعمل على المنفذ 3000 — ضعه خلف nginx
```

> ⚠️ مهم للصيغ القديمة (doc/ppt/xls/rtf/odt): **LibreOffice لازم يكون مثبتًا على الخادم**. بدونها صيغ PDF/DOCX/PPTX الحديثة تشتغل عادي.

## 📋 أبرز إصلاحات وتحسينات الإصدار 2

1. **إصلاح النقل والحذف**: أزرار نقل المستند للتصنيف وحذفه كانت تُنادى على endpoints غير موجودة — أُضيف `PATCH/DELETE /api/documents/[id]` مع حذف الملفات من التخزين أيضًا.
2. **عزل البيانات (v2.1)**: ملفات الزائر لم تعد تُنقل إلى الحساب عند التسجيل/الدخول — كل حساب يبدأ فاضيًا ويرى ملفاته فقط، وكوكي الزائر يُمسح عند الدخول والتسجيل والخروج.
3. **قفل ثغرتين**: `/api/chat` و`/api/reanalyze` كانا مفتوحين بدون أي حماية (حرق مفاتيح Gemini) — الآن محميان بالهوية والكوتة.
4. **تعقيم تسجيل الدخول**: الإدخال كان يُدمج مباشرة في فلتر قاعدة البيانات — أصبح استعلامات منفصلة آمنة.
5. **توحيد Gemini**: كان 3 موديلات مختلفة + 3 مكتبات — الآن عميل واحد (`lib/ai/gemini.ts`) يدير كل شيء: الموديلات من البيئة، تدوير 50 مفتاحًا، إعادة المحاولة.
6. **إصلاح ffmpeg**: كان المسار مثبتًا على `ffmpeg.exe` (ويندوز فقط) — يعمل الآن على لينكس وويندوز وماك.
7. **إصلاح قراءة PPTX**: كانت عبر عملية فرعية هشّة — أصبحت مباشرة داخل العملية مع ترتيب شرائح صحيح.
8. **إصلاح صفحة الخطط للأدمن**: كانت فيها أخطاء صياغة تمنع فتحها إطلاقًا.
9. **توحيد نظام الاستخدام**: كانت هناك نسختان متضاربتان — أصبح مصدرًا واحدًا (`lib/usage.ts`) يدير: التحليل، الشات، الدروس الصوتية والمرئية.
10. **استكمال الملفات الناقصة**: `package.json` و`tsconfig.json` و`next.config.ts` و`postcss.config.mjs` + سكريبتات SQL الكاملة + Dockerfile + README.

## 🆕 إصلاحات v2.1 (نوفمبر 2026)

1. **إصلاح توليد فيديو الدروس على ويندوز** (خطأ `ffmpeg exited with code 4294967294 / Error opening input file … .r.txt`):
   - مجلد العمل المؤقت صار `os.tmpdir()` بدل `/tmp` الثابت (على ويندوز كان بينحلّ لحسب درايف التشغيل).
   - مسارات قوائم الـ concat بشرطات مائلة للأمام — الشرطة الخلفية `\` كانت بتُؤكل كمَحرف تهريب داخل قوائم ffmpeg فتبوّظ المسارات.
   - عند فشل الدمج السريع: حل بديل بإعادة ترميز عبر `filter_complex` بدون أي ملف قوائم، مع تطويع تلقائي لمقاسات/ترددات المقاطع المختلفة.
   - رسائل خطأ واضحة بالعربي بدل stderr الخام.
2. **عزل بيانات المستخدمين**: إلغاء نقل ملفات الزائر إلى الحساب الجديد عند التسجيل أو الدخول، ومسح كوكي الزائر عند الخروج أيضًا — كل مستخدم يرى ملفاته فقط على أي جهاز.
3. **إصلاح نقل الملف بين الفولدرات**: كانت القائمة بتعرض البيانات القديمة بعد النقل (stale closure) فبِيبدو النقل «مش بينفذ» — الآن يتم جلب البيانات الجديدة بعد النقل مباشرة + رسالة نجاح/خطأ واضحة في المكتبة وصفحة التصنيفات.
4. **الدروس منظمة تحت الفولدرات والملفات**: صفحة «دروسي» بتعرض الدروس هرميًا (📁 فولدر ← 📄 ملف ← 🎧/🎬 دروس)، وفوق ذلك دروس كل فولدر تظهر داخل المكتبة نفسها.
5. **أمان التبعيات**: Next.js 15.5.29 + تجاوزات postcss/tar/sharp + SheetJS الرسمي — `npm audit` = صفر ثغرات (متستخدمش أبدًا `npm audit fix --force` لأنها هترقّي لـ Next 16 وتبوّز المشروع).
6. **حفظ الدروس وعرضها**: أي درس اتولد بيتحفظ في قاعدة البيانات والتخزين وبيظهر تاني لما تفتح الملف أو صفحة «دروسي» — مش بيتولد من جديد.
7. **تدوير مفاتيح Gemini الذكي (429)**: بدل ما كل المفاتيح تتعرض في ثواني — المؤشر بيلف على المفاتيح بالتساوي (كل نداء ناجح يبدأ من المفتاح اللي بعده)، وعند حد الاستخدام المؤقت (429) بيتسّنى حسب مدة الـ retry اللي جوجل بيطالبها ويعيد المحاولة قبل ما يجرب مفتاح تاني، والمفاتيح المرفوضة/الملغية بتتخطى فورًا، ورسالة الخطأ بقت توضح السبب والحل بالعربي.
8. **لهجة مصرية في الدروس** 🇪🇬: خيار «لهجة التعليق الصوتي» في نافذة إنشاء الدروس — **مصري (افتراضي)** زي المُحاضر المصري في الفيديوهات التعليمية، أو **فصحى** مبسطة. العناوين والنقاط على الشرائح فصحى مبسطة دايمًا، والتعليق المنطوق هو اللي بيتبع اللهجة المختارة — شغال في الشرح المباشر والبودكاست والفيديو.
9. **الباقة المجانية بدون توليد دروس**: توليد الدروس الصوتية والمرئية بقى **للباقات المدفوعة فقط** (سعر الباقة > 0) وبتحسب ضمن حد باقتها اليومي — الحساب بينفع لأن خدمات الذكاء الاصطناعي بتتكلف. المستخدم في المجاني بيشوف رسالة واضحة إنه يرتقي، وكروت الباقات في صفحة الاشتراكات بتوضح «دروس صوتية/فيديو: متاحة/غير متاحة» وحد اليوم.
10. **تجديد الاشتراك بيكوّن الأيام (مش بيصفّرها)**: عند إدخال كود تجديد واشتراكك لسه ساري، المدة بتتزاد على الأيام المتبقية بدل ما تبدأ من النهاردة — ومفيش لازمة تختار الباقة الصح، **الكود نفسه هو اللي بيحدد الباقة**. وبيطلعلك رسالة بالأيام المضافة والمتبقية بعد التفعيل.
11. **متابعة الأيام المتبقية في السايدبار**: كارت «👑 اسم الباقة — باقي X يوم» ظاهر طول الوقت في القايمة الجانبية، وبيتحول لأصفر مع تنبيه «جدّد دلوقتي» لما يبقى 3 أيام أو أقل — وصفحة الاشتراكات بتعرض نفس المعلومة مع تاريخ الانتهاء وزرار «تجديد بكود تفعيل» على الباقة الحالية نفسها.

## 🆕 نظام الاشتراكات والدفع v2.2 (نوفمبر 2026)

> **الترقية:** شغّل `sql/02_upgrade_subscriptions.sql` مرة واحدة في Supabase SQL Editor — هو بيعمل كل حاجة: جداول جديدة، خطة مجانية مدى الحياة، وتحويل الاشتراكات المجانية القديمة (٣٠ يوم) لمدى الحياة، وبيفعّل الخطة المجانية لأي مستخدم ملوش اشتراك ساري.

1. **الخطة المجانية مدى الحياة بدون أي تفعيل**: أي حساب جديد بياخد الخطة المجانية تلقائيًا لحظة التسجيل ومدتها 100 سنة (عملياً مدى الحياة) — مفيش كود ولا دفع ولا زرار «تفعيل المجاني» في صفحة الاشتراكات خالص. الخطة المجانية ليها حدود يومية بس (10 ملفات/يوم افتراضيًا — قابلة للتعديل من لوحة الأدمن)، ومن غير دروس صوت/فيديو.
2. **حدود رفع الملفات لكل باقة + رسالة واضحة**: لما المستخدم يعدي حد باقته يطلعله: «لقد وصلت إلى أقصى عدد لرفع الملفات اليوم (X من Y) في باقة "..." انتظر حتى الغد، أو اشترك في باقة أعلى من صفحة الاشتراكات». ولو حصل خطأ نادر والاشتراك ضايع، النظام بيعالجها لوحده وبيرجع يفعّل الخطة المجانية.
3. **الدفع قبل أي كود تفعيل**: لما المستخدم يختار باقة مدفوعة، أول حاجة بتظهرله **طرق الدفع** (فودافون كاش / إنستاباي / تحويل بنكي — الأدمن بيعدلها نص حر من لوحة الأدمن) + خانة **رقم عملية التحويل/المرجع (إلزامي)** + زرار «حوّلت — ابعت الطلب للإدارة» — والطلب بيتسجل للأدمن للمراجعة.
4. **التجديد بيكوّن الأيام**: التجديد نفس التدفق — المستخدم يدفع تاني وبيبعت الرقم المرجعي، ولما الأدمن يقبل بيتضاد فوق المتبقي فورًا (تراكمي بين الباقات المدفوعة — مش بيفقد يوم واحد). والانتقال من المجاني للمدفوع بيبدأ من يوم الدفع نفسه، وبعد ما الباقة المدفوعة تخلص المستخدم بيرجع للخطة المجانية **تلقائيًا** بدون أي تدخل.
5. **كود التفعيل لأول اشتراك**: بعد ما الأدمن يقبل دفعة أول اشتراك، بيتولد تلقائيًا **كود تفعيل مربوط بحساب المستخدم ده** (مبيشتغلش مع حد تاني) — الأدمن بينسخه ويبعته للمستخدم، والمستخدم يدخله من قسم «استلمت كود تفعيل من الإدارة؟» في صفحة الباقات — واشتراكه بيبدأ من يوم ما دفع نفسه.
6. **تنبيه قرب الانتهاء**: كارت الاشتراك في السايدبار بيعرض اسم الباقة + الأيام المتبقية + **تاريخ الانتهاء**، ولما يبقى 3 أيام أو أقل بيتحول أصفر مع «اشتراكك على وشك الانتهاء — جدّد دلوقتي» — والضغط عليه بيفتح صفحة الاشتراكات مباشرة. والخطة المجانية بتظهر «مدى الحياة ✓» من غير تاريخ انتهاء.
7. **ترقية فورية من داخل نافذة الدروس**: لما مستخدم المجاني يحاول يولّد درس صوت/فيديو، الرسالة بتظهر معه **كروت الباقات المدفوعة** (السعر والمدة وحدود الدروس) وزرار «اشترك دلوقتي» — من غير ما يسيب الصفحة.
8. **لوحة أدمن المدفوعات** (`/admin/payments`): كل طلبات الدفع (معلقة/مقبولة/مرفوضة) + شارة نوع الطلب (أول اشتراك/تجديد) + قبول/رفض + **إحصائيات التكلفة**: إجمالي المقبوضات بالجنيه + عدد الدروس الصوتية والمرئية المولدة (اليوم والإجمالي) عشان تعرف تكلفة خدمات الذكاء الاصطناعي مقابل الدخل.
9. **مراجعة الأدمن إلزامية — مفيش تفعيل ذاتي**: المستخدم مبيقدرش يتفعل لوحده مهما حصل — أي دفعة بتستنى موافقتك، وبيوصللك إشعار بعدد الطلبات المعلقة في السايدبار (بادج أحمر جنب «أدمن: المدفوعات»).
10. **باقات افتراضية للتثبيت الجديد**: الخطة المجانية (10 ملفات/يوم + مدى الحياة + بدون دروس) وباقة «الأساسية» المدفوعة كمثال (عدّل الأسعار والحدود من لوحة الأدمن).

## 🆕 تدفق الدفع بمراجعة الأدمن v2.3 (نوفمبر 2026)

> **الترقية:** شغّل `sql/03_payment_flow_admin_approval.sql` مرة واحدة في Supabase SQL Editor (بعد `02`) — بيلغي الموافقة التلقائية نهائيًا، ويضيف نوع الطلب (أول اشتراك/تجديد)، وأعمدة ربط كود التفعيل بالمستخدم والدفعة ويوم بداية الاشتراك.

### التدفق الكامل (زي ما الإدارة عايزاه بالظبط)

**أول اشتراك في باقة مدفوعة:**
1. المستخدم يختار الباقة ← يشوف طرق الدفع (المحافظ) والمبلغ ← يحوّل ← يكتب **رقم عملية التحويل (المرجع)** — إلزامي — ويضغط «حوّلت — ابعت الطلب للإدارة».
2. الطلب بيتسجل «قيد المراجعة» وبيظهر للمستخدم في صفحة الباقات (كارت أصفر)، وبيظهر للأدمن في اللوحة + بادج أحمر في السايدبار.
3. الأدمن يتأكد إن الفلوس وصلت المحفظة فعلًا ← يضغط **«قبول وإنشاء كود تفعيل»** ← بيتولد كود زي `AIB-XXXXXXXX` **مربوط بحساب المستخدم ده بس** — بيظهر للأدمن بزرار نسخ.
4. الأدمن يبعت الكود للمستخدم (واتساب/أي وسيلة) ← المستخدم يدخله في صفحة الباقات ← اشتراكه بيشتغل، **والبداية بتتحسب من يوم ما هو حولت الفلوس** (مش من يوم إدخال الكود).

**تجديد اشتراك:**
1. نفس خطوات الدفع بالظبط (المستخدم يقدر يجدد بنفسه في أي وقت من صفحة الباقات أو كارت السايدبار).
2. بيوصل الأدمن إشعار: «المستخدم فلان الفلاني — الباقة كذا — المبلغ كذا — رقم مرجعي كذا — تجديد».
3. الأدمن يتأكد من الفلوس ← يضغط **«قبول وتجديد فوري»** ← الاشتراك بيتجدد **على طول من غير أي كود**.
4. لو الأدمن فتح الرسالة متأخر (يوم مثلًا) — **المدة بتتحسب من يوم ما المستخدم أكد الدفع** (بعت الرقم المرجعي) مش من يوم الموافقة — المستخدم مبيخسرش يوم، ولو اشتراكه لسه ساري الأيام بتتضاف فوق المتبقي.

> **ملاحظة:** مفيش أي تفعيل تلقائي نهائيًا — حتى لو حد كتب رقم مرجعي عشوائي، اشتراكه مش هيشتغل غير بعد ما انت تراجع وتوافق بإيدك.

## 🆕 برجَي المفاتيح: مجاني ومدفوع v2.3.2 (نوفمبر 2026)

نظام توجيه المفاتيح حسب خطة المستخدم — الهدف: **العميل اللي دفع فلوس عمره ما يتصد بمفتاح مجاني مستنزف**.

### القواعد

| مين؟ | بيستخدم إيه؟ |
| --- | --- |
| ضيف / مستخدم مجاني | برج المجانيين فقط (`GEMINI_API_KEY_1..50`) — لا يلمس مفاتيح الفلوس أبدًا |
| مشترك مدفوع | برج المدفوعين أولًا (`GEMINI_PAID_API_KEY_1..50`)، ولو فشل بالكامل → ملجأ مجاني تلقائيًا (الدرس يتولد مهما حصل) |
| بدون مفاتيح مدفوعة في `.env.local` | تشغيل عادي على البرج المجاني — **صفر كسر، التفعيل لاحقًا من غير رفع كود** |

### نطاق التوجيه

- ✅ دروس صوت/فيديو (`/api/lessons`) + الشات (`/api/chat`) — نقطة القرار من سعر الباقة الفعال في `checkQuota` (price > 0 = paid).
- تحليل المستندات/OCR/نسخ الميديا يفضل على البرج المجاني (عمليات الرفع المتاحة للجميع).

### خطوات التفعيل لاحقًا (بعد الدفع)

1. في Google Cloud: فعّل Billing على المشروع المخصص للمدفوعين → يرتقى تلقائيًا لـ **Tier 1** (حدود أعلى بكثير من المجاني — RPM مئات/آلاف وبدون حد يومي صارم؛ الحصة بتتحسب **على المشروع مش المفتاح**).
2. اعمل مفتاح API من المشروع ده وضيفه في `.env.local`:
   ```env
   GEMINI_PAID_API_KEY_1=AIza...
   ```
3. Restart للسيرفر خلاص — الطلبات المدفوعة هتتحول للبرج الجديد فورًا (شوف اللوج: `tier=paid → برج المدفوعين (N مفتاح) + ملجأ مجاني`).
4. حط **Budget Alert** في Google Cloud عشان ينبهك لو الصرف عدى حد محدد.

⚠️ **أمان**: مفاتيح الفاتورة = فلوس حقيقية — تفضل في `.env.local` على السيرفر فقط، ولو أي مفتاح اتسرب امسحه من جوجل فورًا.

اختبار النظام: `npx tsx scripts/test-key-pools.ts` — 16 فحص للتوجيه والملجأ والدوران اللاصق.
